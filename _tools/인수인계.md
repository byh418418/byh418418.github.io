## 3. 파일 구조

```
index.html          ← 페이지 전체 (CSS·JS 전부 인라인, 약 500줄)
posts-data.js       ← window.FOTOPOP_POSTS 배열
images/             ← 원본 (긴변 1920px)
images/thumb/       ← 썸네일 (긴변 800px)
images/video/       ← 릴스·동영상 (720p h264, faststart)
fonts/              ← Aileron (없으면 Helvetica 폴백, 사이트는 정상 동작)
CNAME               ← fotopopgt.com
_tools/             ← 작업 스크립트 + 이 문서 (커밋됨, 사이트 동작과 무관)
google-maps-photos/ ← 구글 비즈니스 프로필용 (gitignore, 로컬에만 존재)
.backup-YYYYMMDD/   ← 작업 전 백업 (gitignore, 로컬에만 존재)
```

### posts-data.js 한 항목

```js
{
  "title":    "짧은 제목",
  "caption":  "인스타 캡션 원문",
  "images":   ["파일명.jpg", ...],  // 캐러셀 순서. 영상은 포스터 jpg가 자리를 차지
  "cover":    "대표.jpg",
  "location": "Majadas Once · Cayalá",
  "tags":     ["해시태그"],
  "type":     "post" | "reel",
  "videos":   { "포스터.jpg": "영상.mp4" },   // 비어있으면 사진만
  "date":     "2026-09-12"
}
```

모달은 슬라이드 파일명이 `videos`에 있으면 `<video>`, 없으면 `<img>`로 렌더링.

## 4. CSS에서 반드시 지킬 것 (실제로 터졌던 버그)

**① 섹션에 `padding: 40px 0` 같은 단축속성 금지**

`.wrap{padding:0 28px}`의 좌우 여백이 통째로 덮여서 모바일에서 글자가 화면 끝에 달라붙음. 실제로 좌우 여백이 **0px**이었던 적 있음. 세로 여백만 줄 때는 **`padding-block`** 사용.

**② 부스 그리드 span 규칙**

데스크톱은 6열에 `span 2`/`span 3`로 3+2 배치. 모바일(≤780px) 1열로 바꿀 때 **span 규칙까지 `grid-column:auto`로 되돌려야 함.** 안 그러면 `:last-child:nth-child(odd){span 2}`가 암묵적 열을 만들어 `80px / 278px`로 찌그러짐.

> 부스 개수가 바뀌면 이 nth-child 규칙도 같이 점검할 것.

## 5. 인스타 새 게시물 반영 (로컬 전용)

### export 설정

인스타 → 계정 센터 → 내 정보 다운로드

- **형식: JSON** (HTML은 파싱 불가)
- **기간: 전체 기간** · **미디어 품질: 고화질**
- 정보 맞춤 설정: **"콘텐츠"만** (전체 선택하면 DM까지 딸려옴)

### 순서

```bash
cd <저장소>/_tools

# 1) 백업
mkdir -p ../.backup-YYYYMMDD && cp ../posts-data.js ../index.html ../.backup-YYYYMMDD/

# 2) build_data.py main() 안의 base 경로를 방금 만든 백업으로 수정
#    base = os.path.join(SITE, '.backup-20260918', 'posts-data.js')

python3 build_data.py     # 3) posts-data.js 병합 + manifest.json 생성
python3 build_media.py    # 4) 이미지·영상 처리 (멱등 — 끊기면 반복 실행)
node verify.js            # 5) 검증 (jsdom 필요)
```

### 겪었던 함정

- **mojibake**: export JSON이 `Ã`, `ð`로 깨져 있음. `fix()`가 latin-1 → utf-8 복원. 직접 파싱하면 반드시 처리.
- **릴스 폴더 위치가 export마다 다름**: 8월분 `media/reels/`, 9월분 `media/other/`. `reels.json`의 `uri` 값을 보고 판단.
- **영상 인코딩 중단**: bash 호출 1회당 약 3분 제한. 끊기면 마지막 mp4가 깨진 채 남으므로 `ffprobe`로 전수 검사 후 재인코딩.
- **파일 삭제 차단**: `rm`이 "Operation not permitted"면 `allow_cowork_file_delete` 도구로 권한 요청. 안 되면 `cat 새파일 > 기존파일`로 덮어쓰기.
- **중복 방지**: 미디어 ID로 dedupe. 손으로 고친 캡션은 보존됨.

## 6. 배포

**로컬 모드**: 샌드박스에 GitHub 인증이 없어서 **사용자가 GitHub Desktop으로 직접** commit → push.

> 함정: Claude가 `git status`를 돌리면 `.git/index.lock`이 남아 GitHub Desktop 커밋이 "A lock file already exists"로 실패할 수 있음. 그 파일을 지우면 해결.

**클라우드 모드**: Claude가 직접 commit·push 가능. 작업 끝나면 **반드시 push**할 것 — 컨테이너가 사라지면 작업분도 같이 사라짐.

양쪽 다 push 후 1~2분 뒤 fotopopgt.com에서 **Ctrl+F5** (캐시 때문에 안 바뀐 것처럼 보임).

## 7. 스크립트 (`_tools/`)

| 파일 | 역할 | 클라우드 |
|---|---|:---:|
| `verify.js` | jsdom으로 index.html 실행 → 렌더링·모달·영상 전환 18항목 검증 | ✅ |
| `build_data.py` | export JSON → posts-data.js 병합·정렬 | ❌ |
| `build_media.py` | 이미지 리사이즈+썸네일, 영상 720p 인코딩+포스터 (멱등) | ❌ |
| `gmaps_sort.py` | 사진을 지점별 폴더로 분류 + 구글 권장 규격 리사이즈 | ❌ |
| `gmaps_review.py` | 지점별 검토용 HTML 생성 | ❌ |

경로는 스크립트 위치(`_tools/`의 상위 = 저장소 루트) 기준이라 **어디에 clone해도 그대로 동작**함.
`verify.js`는 jsdom 필요: `npm install jsdom` 후 `NODE_PATH` 지정.
인스타 관련 스크립트는 export 폴더가 없으면 안내 메시지를 내고 종료함.
